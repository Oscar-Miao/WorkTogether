## 可重复验证

在 demo 根执行：

```powershell
pnpm check
pnpm check:structure
pnpm test
pnpm test:e2e
pnpm build
pnpm check:smoke
```

测试使用独立 .local/reports 子目录和合成账号，不向实际开发库填充夹具。浏览器覆盖桌面和手机的登录、聊天、资料保存、邀请/接收、成员移除、历史分页、完整资料编辑、默认关闭的清理入口；新发消息断言实际进入可视区域，历史任务异步加载不再使跟随滚动停在中段；没有页面 JavaScript 异常。截图和 HTML 报告位于 .local/reports/playwright。

Pi 测试启动锁定的真实 CLI，模型由本机合成协议服务替代。这能验证 RPC、工具和预算边界，不能证明真实供应商可用性、模型回答质量或企业网络兼容。开发和测试数据库使用 PGlite，未宣称 PostgreSQL 实例测试通过。

## 保留策略的当前边界

云端维护由 TEAM_AGENT_RETENTION_ENABLED 控制，默认 false，未修改现有 .env.local 来启用。开启后的定时任务处理 30 天私有正文、180 天审批正文/审计、过期凭证和 24 小时 HTTP 幂等记录；每小时分批执行。任务终态、快照和来源元信息继续保留，有助于追溯；这比 180 天保留更长，后续需补归档策略。

Owner 提前清理仅涉及云端私有原始事件和未发布成果；活动、待核查、有未终结尝试或保留标记的任务受保护。日志每批最多 1000 条，超出部分需重新预览后继续。共享成果、会话、快照、资料原文与本机文件不会被该入口清理。

本机 spool 按实际 UTF-8 正文字节累计，ACKed 事件仍计入上限；96 MiB 时拒绝继续追加并停止执行，为停止证据留余量。尚无 ACK 后 7 天的自动清理、本机缓存正文清理或 180 天账本归档工具；终态去重账本继续保留。worktree 清理由 Owner 按运行手册核对后操作，代码不自动删除未提交成果。以上属于后续维护工作，不能据此声称生命周期需求已全部达成。

上下文原文整理前检查最多 10000 条/8 MiB，超出显式拒绝；初始模型输入最多 96000 字节，不通过静默丢弃早期限制来满足预算。合成测试覆盖消息超过 1000 条时截止点和历史读取仍正确。

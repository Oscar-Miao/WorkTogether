# Bridge 配对、取消和故障核查

## 配对与撤销

首次在 Web 生成 5 分钟单次配对码，Owner 本机显式选择 Git 仓库和可选修改前缀。Bridge 主动连接云端，不监听本机 HTTP/PTY，不需要向公网开放本机端口。

设备撤销后，网页和普通设备令牌均不能恢复其执行权限。正在执行的任务依赖最迟 60 秒到期的本机租约停止；正常联网时每 20 秒续租。原任务停止后仍允许一次性挑战签名的停止回执，保留真实终态。换设备须核清旧任务并使用新的私有数据目录配对。

## 取消

在任务详情点击“停止执行”。CANCEL_REQUESTED 表示已保存意图，CANCELLED 才表示执行已确认停止。停止失败或原进程句柄丢失时进入 RECONCILING；不要用刷新、修改数据库状态或重复提交来跳过核查。

取消不会撤销已经发生的修改，worktree 原样保留。报告统一注明是否运行测试；首版测试工具关闭。

## 只读查看与人工核查

```powershell
pnpm bridge -- --inspect --data-dir ".local/bridge/default"
```

该命令以只读方式打开 SQLite，不改写运行状态，可在 Bridge 运行时使用。账本输出只有 attempt ID、状态、PID 和回传标记，不打印设备私钥或模型凭据。

遇到 uncertain：

1. 保留设备私有数据、SQLite WAL、事件和 worktree；停止该数据目录的 Bridge。
2. 根据日志和 attempt ID 核对原 Pi/Git 进程、启动时间及其子进程。Windows 可使用任务管理器或 Get-CimInstance Win32_Process。PID 可能复用，不能仅凭一个数字杀进程。
3. 对确认属于本次尝试的残留进程树，Owner 通过操作系统工具停止并核实。平台不会自动把“PID 不存在”当作所有子进程都已停止。
4. 确认后记录检查方法与时间，再执行：

```powershell
pnpm bridge -- --reconcile attempt_REPLACE --stop-evidence "填写实际核查时间、进程树检查方法和确认停止的结果" --data-dir ".local/bridge/default"
pnpm bridge
```

reconcile 需要独占 Bridge 数据目录；如果记录的 PID 仍存在会拒绝。它保存显式人工证明，不能代替操作系统核查。下次连接回传为 MANUALLY_RECONCILED / FAILED，原结果未确认，不自动重跑。需要重新执行时新建任务、重新审批。

## 常见错误

| 错误                              | 处理                                                                                   |
| --------------------------------- | -------------------------------------------------------------------------------------- |
| MODEL_NOT_CONFIGURED              | 在本机设置实际 PI_MODEL、PI_PROVIDER 与对应凭据，或显式使用 inspection 检查链路        |
| MODEL_ERROR / PI_REQUEST_REJECTED | 检查本机模型地址、鉴权、模型能力和 Owner 私有诊断；不要将网络/模型错误当作代码测试失败 |
| BUDGET_EXCEEDED                   | 调用预算已停止新的 provider 请求；调整输入后重新审批，不能复用旧许可扩大预算           |
| APPROVAL_STALE                    | 引用或输入版本已变化，修订任务并重新查看来源                                           |
| BRIDGE_ALREADY_RUNNING            | 同一数据目录有活动实例，使用原实例，不启动第二个 Bridge                                |
| STOP_UNCONFIRMED                  | 保留执行槽位，按人工核查流程确认原进程树                                               |
| SPOOL_LIMIT / 磁盘不足            | 停止新增执行，保留尚未确认事件；恢复磁盘后连接补传，不删除账本来“重试”                 |

## Owner 账号恢复

停止 API 后，以服务运行身份在 demo 根运行 pnpm reset:owner。命令通过配置中的 Owner 邮箱定位现有账号，生成随机密码，撤销全部旧 Owner 会话并写审计；新凭据仅保存在配置数据根 private/owner-recovery.json。不开放网页恢复接口，不修改业务数据，不在日志或命令参数中传递密码。PGlite 单进程锁会阻止带着活动 API 执行该操作。核实新密码后按本机凭据保管流程处理恢复文件。

## 清理与凭据恢复

云端已实现维护服务，执行开关 TEAM_AGENT_RETENTION_ENABLED 默认 false。关闭时 Owner 仍可在任务详情“数据保留”预览影响、标记或解除保留，但不能删除正文。开启会在服务启动及每小时分批处理到期数据；本次未开启现有数据清理。启用前应在部署环境验证备份恢复和实际保留政策，参见验证记录。

云端自动处理 30 天私有日志和未发布成果正文、180 天审批正文/审计，以及过期凭证和 24 小时 HTTP 幂等记录。Owner 提前清理只处理当前预览中的云端私有正文，必须提交原因和当前任务版本；每批日志最多 1000 条，完成后重新预览。活动、待核查、有未终结尝试及保留任务受保护；共享成果、快照和资料保留。正文移除后显示缺失标记和哈希，不能再发布或视为完整证据。

云端清理不处理本机文件。本机 spool 和结果尚无自动到期清理，终态去重账本继续保留；spool 按 UTF-8 字节累计，到 96 MiB 会拒绝追加并停止执行。不要删除未 ACK 事件或整个账本来释放容量。处理磁盘容量前先停止 Bridge、完成结果补传并保留备份；自动维护工具仍待补齐。

清理 worktree 前必须确认对应 attempt 已停止且结果已回传，检查 git status 和未跟踪文件，导出修改，并核对 git worktree list 中的绝对路径。使用 Git 的 worktree remove，禁止模糊匹配目录或 force 清理。

不要把 config.json 中设备身份与另一份私钥混用，不覆盖旧账本。配置丢失时先核查并撤销设备，再使用新目录配对。云端许可签名私钥必须连同数据一起备份；模型凭据与设备私钥只由 Owner 本机管理。

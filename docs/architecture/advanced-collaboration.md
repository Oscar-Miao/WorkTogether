# 进阶版运行与代码指南

更新：2026-10-19。对应父目录进阶 PRD v2.0。本文描述实际代码；产品质量、真实组织接入和企业运维门槛另见 [覆盖与验收](../qa/advanced-status.md)。

## 1. 进入新功能

继续在 demo 根执行 pnpm dev。已有安装需按锁文件更新依赖；不要重新初始化已有账号或复制测试数据库覆盖项目数据。

- 主设备侧栏 →“空间、项目与成员范围”：创建空间、项目，添加已有团队账号。
- 有两个以上可访问项目时，群列表标题旁出现唯一切换入口。切换会重建页面，隔离旧请求、侧栏和资料引用。
- 群成员侧栏 →“群设置与讨论分叉”：观察开关、分叉、归档、恢复、退出、群管理移交。
- 目标详情 →“分工、依赖与版本”：查找关联目标、建立依赖、确认交接、提交修订、创建只读分工计划和核验集成。
- 主设备侧栏 →“多设备、并发与主节点代次”：设置配额、配对其他 Runner、绑定执行主节点。
- 主设备侧栏 →“观察覆盖、质量与审计”：查看可见范围的队列、用量、质量记录和审计 JSON。

默认项目沿用旧成员和数据。默认执行配额仍为 1 设备 / 1 并发，必须由维护者显式调整后才开放 Runner 池。管理员拥有治理权限，不因此自动成为其他私群成员。

## 2. 空间、身份与项目事实隔离

根数据库保存账号、会话、空间及项目目录。旧项目继续使用原根数据库；新增项目分别拥有自己的群聊、资料、目标、设备、签名密钥和运行状态。

| 运行方式           | 新项目事实的位置                                    |
| ------------------ | --------------------------------------------------- |
| PGlite 开发        | 原服务数据目录/projects/项目ID/postgres             |
| PostgreSQL         | scope\_项目ID schema，每条连接固定 search_path      |
| 项目签名和私有状态 | 原服务数据目录/projects/项目ID/private 等项目子目录 |

没有对 SQL 做字符串改写。请求选择具体 Services 实例，所有普通查询与事务天然进入该实例的数据库命名空间。后台观察器和调度器持有具体项目实例，不依赖浏览器当前选择。

组织目录使用 /api/v3。项目业务继续使用 /api/v1 与 /api/v2；新增项目在地址前加 /p/项目ID。请求每次核查根账号和项目成员关系。设备短期配对码及签名通道在相同项目命名空间验证，不要求设备携带人类 Cookie。

项目成员被撤销时，本机执行身份同步失效、关联群成员关系移除、活动任务收到系统取消。未打开的项目在恢复时以根目录重新同步成员。根身份撤销会传播到所有已打开项目。私群仍需显式成员关系。

本地实例限制同时打开 16 个新增项目，防止无限启动 PGlite 实例。该限制不是企业容量承诺。PostgreSQL 的 schema 隔离代码已提供，实际部署与连接池容量仍需验证。

## 3. 连接当前项目的 Runner

使用网页生成的命令，其中已包含项目路径与独立 Bridge 数据目录。手动示例：

```powershell
pnpm bridge -- --pair YOUR_PAIRING_CODE --api "http://127.0.0.1:3001/p/prj_YOUR_PROJECT_ID" --repo "D:/your-pilot-repository" --runtime inspection --data-dir ".local/bridge/project-runner-a"
```

使用实际项目 ID 替换占位符。默认项目不加 /p 路径。每个 Runner 使用不同数据目录；真实 Pi 的模型配置仍在运行 Bridge 的设备上完成，不通过浏览器传输。

inspection 实际创建 worktree 和文件报告，不调用 AI。接入模型后可选择 --runtime pi，代码工具保持既有的读文件、目录枚举、授权原文回读和精确编辑。新建／删除文件、任意 Shell、测试命令、推送与部署未开放。

## 4. 目标协作规则

- depends_on 表示当前目标依赖另一目标。提交关系时检查双方版本和可见性，并在项目事务中拒绝环路。
- 人工交接保留发起者、接手者、进度说明和目标版本。只有指定接手者能接受或拒绝，接受前原负责人仍有效。
- 修订先保存旧快照和新提议，再请求旧任务停止。未知是否停止时不能应用新版本；终结确认后重新判断。
- 上游修订会阻塞／停止受影响的下游；历史任务成功与当前成果有效性分别保存。
- 合并提议目前通过 API 记录为 proposed，保留双方版本和原因；自动执行合并与跨群历史合并没有开放。
- 群归档保留历史，拒绝新消息及执行。管理移交使用 manager_id，created_by 不被改写。
- 分叉复制截止点及当时成员到私群，记录祖先与说明；后续消息不自动合入。父群成员撤销会传至派生群，相关活动执行同时停止。

聊天分叉和 Git 分支是不同的实体。执行仍按冻结 base_commit 创建独立 task 分支；没有自动 Git 合并、方案胜出后的自动集成或分支移植工具。

## 5. DAG、并行与真实成果流转

维护者可为尚未执行的目标创建有名称和依赖的只读步骤。计划冻结目标版本、策略版本、仓库基线与步骤效果指纹。相同有效步骤不能通过改步骤名称再次启动。

1. 已满足依赖的独立步骤进入真实任务队列。
2. 每个设备最多一个未终结执行，项目总并发受配额约束。
3. 本版资源锁以项目代码资源为粒度：只读可共享，写入排他；未知状态继续占用资源。
4. 下游读取上游真实报告的授权引用。成果 ID、哈希与原群受众进入冻结上下文，长报告可经短期许可回读。
5. 成果缺失、被清理、被标为过期或来源变化时，下游阻塞／撤销，不能用空报告继续推进。
6. 全部步骤结束只进入 awaiting_verification。成员提交集成核验依据后才结束目标，并明确这是人工确认，不是自动测试证明。

计划状态、步骤与队列存储在数据库。重启后不会将未知执行当成新步骤重跑。自动多 Agent 拆解、不同能力角色的自动授权、并行代码集成和容器隔离尚未开放。

## 6. 主节点代次与安全边界

首次切换执行主节点增加 epoch，派发描述符和签名许可绑定该代次。Bridge 在准备 worktree 前取得有效续租，续租再次验证代次、主节点租约、用户、群、政策和来源。

主节点心跳延长 40 秒领导租约；执行许可按既有最多 60 秒租约续期，Bridge 每秒检查过期。停止先发 RPC abort，必要时终止进程树，并等待证据。租约过期不证明原进程已停，因此仍保留未知执行的资源占用。

相同节点重复绑定只续期，不增加代次。更换节点遇到未核清执行时拒绝切换，不能凭一个按钮放行新的写入。

当前是单 API 控制进程中的执行准入与手工节点切换机制。绑定不会把正在运行的协调进程迁移到另一台主设备，也不提供多 API 副本高可用或自动选主。工具检查仍不是操作系统沙箱。

## 7. OIDC 配置

在主 API 环境设置：

```text
OIDC_ISSUER=https://your-identity-provider.example
OIDC_CLIENT_ID=your-registered-client-id
OIDC_CLIENT_SECRET=your-private-client-secret
```

注册回调为 WEB_ORIGIN/api/v3/auth/oidc/callback，启用授权码流程与 S256 PKCE。登录页仅在配置存在时显示组织账号入口。

实现会验证 discovery 发行者、HTTPS、浏览器 state、一次性有效期、PKCE、ID Token 签名、发行者、受众、时间和 nonce。通过验证后仅连接已有且有效、邮箱已核验的团队账号；不会自动创建空间成员或取得私群权限。会话仍可被撤销。

本轮使用真实本地 HTTP 提供商与签名令牌验证协议，没有接入用户企业的真实 IdP。参考：[OIDC 授权码流程](https://openid.net/specs/openid-connect-core-1_0.html#CodeFlowAuth)、[PKCE 验证](https://www.rfc-editor.org/rfc/rfc7636#section-4.6)。

本地团队成员上限默认 10，可通过 TEAM_AGENT_MEMBER_LIMIT 设置 1～500；部署模板默认 50。配额参数不代表容量已达到该人数。

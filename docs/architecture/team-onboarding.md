# 账号注册与团队入驻

团队在界面中对应工作空间，团队内有项目，项目内有群聊。注册建立个人身份；接受团队邀请获得一个指定项目的成员资格；加入群聊仍遵循公开群目录或私群邀请码。Owner 继续表示主设备，不是注册用户的角色。

## 客户操作

1. 打开 Web 登录页，选择“注册账号”，填写名字、邮箱、至少 6 位的内测密码及确认密码（生产模式至少 12 位）。
2. 注册后选择“创建团队”，填写团队与首项目名称；或粘贴团队邀请链接／邀请码，查看团队与目标项目后确认加入。
3. 已在聊天的用户可打开“团队与项目”：桌面在左侧导航底部，手机在聊天头部。可以加入其他团队、创建团队、查看并进入自己的项目。
4. 项目维护者在此入口展开“邀请成员加入当前团队与项目”，生成邀请。可以限定邮箱、设置 1～100 个名额及 1～168 小时有效期，默认单次、24 小时。
5. 复制生成的链接分享给同事。新账号先注册，已有账号直接登录；两者均需确认加入。原始链接只在生成时展示，历史列表支持撤销。
6. 进入项目后创建公开群，其他项目成员可在“创建或加入群聊 → 发现群聊”加入；私群继续使用单独的群邀请码。

其他团队的身份、项目内容和私群不会因注册或加入一个项目而自动开放。进入已有团队也不会获得主设备配对、代码执行策略和其他项目维护权限。

## 接口与职责

| 接口                                                 | 输入                                | 结果与规则                                                               |
| ---------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------ |
| GET /api/v1/auth/options                             | 无                                  | 当前部署是否开启自主注册                                                 |
| POST /api/v1/auth/register                           | email、name、password               | Argon2id 保存密码，建立普通账号及 HttpOnly 会话，不添加团队关系          |
| GET /api/v3/account                                  | 登录会话                            | 用户、CSRF、已加入工作空间和项目                                         |
| POST /api/v3/teams                                   | name、project_name、Idempotency-Key | 同一事务创建团队、首项目和发起人维护权限；重试不重复建团队               |
| POST /api/v3/projects/:id/invitations                | 可选 email、expires_hours、max_uses | 仅项目维护者；单次返回 token，数据库仅存摘要                             |
| GET /api/v3/projects/:id/invitations                 | 登录、项目维护权限                  | 最近 50 条邀请的使用量、期限及撤销状态，不返回令牌或摘要                 |
| POST /api/v3/projects/:id/invitations/:invite/revoke | 登录、CSRF                          | 立即撤销，后续预览及接受被拒绝                                           |
| POST /api/v3/team-invitations/preview                | token                               | 可匿名，持有令牌才可预览团队／项目／期限／剩余名额，不返回名册或受邀邮箱 |
| POST /api/v3/team-invitations/accept                 | token、登录、CSRF                   | 校验邮箱限制与签发者当前权限；事务内消耗名额并加入目标项目               |

工作空间创建不是隐式执行授权。新项目仍需配对 Owner 主设备、设置明确的执行策略，再让 Agent 执行。

## 数据、并发与兼容

- 追加迁移 0011-team-onboarding.sql，不改历史迁移。identity_settings 记录一次性历史成员迁移；重启不再把所有新用户自动加入默认项目。
- org_invitations 存令牌摘要、项目、可选邮箱、名额、期限、签发者与撤销时间；org_invite_acceptances 记录实际使用者，移除后不能使用同一旧邀请重新获得权限。
- 接受邀请、变更项目成员与签发邀请共用项目行锁；名额校验与成员插入在同一事务内，重复接受已加入项目不会再扣名额。
- 已经打开的独立项目会在接受邀请后同步身份，首次响应丢失后再次接受也会重试同步。
- 默认项目与其他项目都逐请求检查显式成员关系。根数据库的名册通过 project_users 视图排除其他团队身份。成员移除只撤销本项目权限并停止其活动工作，保留个人账号和其他项目资格。
- 自主注册与旧邀请开户共用账号配额锁，TEAM_AGENT_MEMBER_LIMIT 为本部署全站账号上限，默认 10，包含初始化维护账号；它不是每个团队独立的名额。
- 注册每 IP 15 分钟最多 10 次，预览邀请每 IP 15 分钟最多 60 次，接受每账号 15 分钟最多 30 次，创建团队每账号 15 分钟最多 20 次。窗口计数持久化，只存主体哈希。
- 原始邀请码不落审计，不自动发邮件。邀请和接受记录按团队事实保留，目前没有邀请记录自动清理界面；过期令牌立即失效，限流过期记录在下次调用时清理。
- 旧邀请开户 /api/v1/invitations/accept 继续支持，但正常客户使用自主注册及带项目范围的团队邀请。
- 旧 /api/v1/members/:id/remove 也统一为项目撤权，不再注销全站账号。

## 配置与实际边界

TEAM_AGENT_REGISTRATION_ENABLED 默认 true；设为 false 后关闭自主注册入口与接口，已注册账号仍可登录并接受邀请。旧初始化维护账号保留，普通客户不必读取它的密码。

现阶段邮箱用作账号标识及邀请限制，按内测要求仅校验邮箱格式，尚未接入邮箱所有权验证、自动发信或自助找回密码。登录页已提供凭当前密码修改密码的入口，修改后原会话全部失效。限定邮箱是字符串匹配，不等同于已验证邮箱或企业域身份；企业试用若要求此保障，应关闭自主注册并通过受控开户或受信企业 OIDC 身份接入。审批式加入、团队公开搜索目录与二维码是后续能力，不宣称已经实现。
